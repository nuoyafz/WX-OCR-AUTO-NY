# 2026-08-18 工作日志

## 任务：分析项目 + 排查"最小化监控"与"实时消息不显示"

### 1. PrintWindow 截图修复（screenshot.py `capture_via_printwindow`）
- 对照抖音"刘嬷嬷"方案 + CSDN/掘金：`PrintWindow(hwnd, hdc, flags=3)`，flags=3 = PW_CLIENTONLY(1)|PW_RENDERFULLCONTENT(2)。
- 发现旧代码两个真 bug：
  - 位图按客户区尺寸建，却用 flags=2(整窗含标题栏)渲染 → 尺寸错配，Qt/QML 黑屏。
  - 黑图检测放在所有 flags 尝试的"最后"，一旦某 flags 返回非0但吐黑图就当成功，不再降级。
- 修复：flags=3→2→0 循环，每次调用后读回像素校验（mean/std），黑图自动降级；新增 `_get_frame_rect_dwm`(DwmGetWindowAttribute EXTENDED_FRAME_BOUNDS) 取真实框架矩形。
- 实测（微信屏幕外非最小化）：flags=3 mean=228/std=46，截到完整清晰微信界面。✔

### 2. "实时消息不显示"根因 + 修复
- 现象：data/messages.db 里全是侧栏垃圾（`往事随风`/`张政权`/`到哪了`/`昨天11:04`/`[图片]`/`洛阳兼职日结群`），挂在当前联系人名下。
- 根因：PrintWindow 截的是**整个客户区（含左侧联系人栏）**，代码只裁"底部 X%"未剔侧栏 → OCR 把联系人列表当聊天消息。
- 修复：新增 `screenshot.crop_chat_region_img()`（按 get_chat_region 比例先剔左30%侧栏/顶8%/底输入框，再取底部比例），替换 main.py 4处全宽裁剪（offscreen主路径、normal兜底、红点路径、minimized闪现2处）+ `capture_chat_bottom` offscreen分支。
- 对比验证：旧裁剪 OCR 出侧栏垃圾；新裁剪只出真实聊天消息（`哈哈那不知道`）。✔

### 关键结论
- "真最小化(WS_MINIMIZE)截图"对 Qt/GPU 微信不可行（最小化时 GPU 停渲染→黑图）。"最小化后能监控"的正确实现 = offscreen 模式（恢复+移到屏幕外 -4000,0，用户不可见但 Qt 持续渲染）。当前 config 已是 offscreen。
- 所有改动需**重启 ui_app.py** 才生效（排查时旧进程 pid=52236 仍在跑旧代码）。
